# CSV / TSV 约定与常见坑

> 依据 RFC 4180 与 Excel 导入导出实践整理。让 AI 生成 CSV、或排查乱码/错列问题时引用本页。

## RFC 4180 核心规则

1. 记录之间以 **CRLF**（`\r\n`）分隔；实际读写时 LF 也普遍被接受。
2. 首行**可以**是表头，字段数与数据行一致。
3. 字段含**逗号、双引号或换行**时，整个字段必须用双引号包围：
   ```csv
   姓名,备注
   张三,"他说, 没问题"
   ```
4. 字段内的双引号用**两个双引号**转义：`"她说 ""你好"" 吗"`。
5. 每条记录字段数应一致；字段可以不加引号（不含特殊字符时）。

## TSV 差异

- 分隔符是制表符 `\t`，字段内一般不允许出现制表符与换行。
- 不需要引号包围机制，换行/制表符通常改写为空格。

## 编码与 Excel 兼容

- 统一使用 **UTF-8**；给 Excel 直接双击打开时加 **BOM**（`\ufeff`），否则中文易乱码。
- 程序间交换数据优先**不带 BOM**，避免部分解析器把 BOM 读进首列字段名。

## 常见坑清单

- [ ] 字段里逗号未加引号 → 整行错列
- [ ] 字段内换行未加引号 → 一行变两行
- [ ] `"` 未写成 `""` → 后续字段全部串位
- [ ] Excel 打开中文乱码 → 缺 BOM 或编码不是 UTF-8
- [ ] 长数字（身份证、订单号）被 Excel 转科学计数 → 生成时前置制表符或显式文本格式
- [ ] 末尾多余空行 → 部分解析器报"空记录"
