# 媒体输出格式增强专项计划（docx / pptx / 图片）

> 目标：三个输出工具在「能出文件」的基础上，达到可交付的排版质量。docx 以中文学位论文/实验报告的严谨版式为基准；pptx 补齐结构页与图文表格版式；图片补齐格式/尺寸/质量控制与报告用图表。
>
> 约束：全部在现有架构内实现（`fs/docgen/*`、`mcp/tool_spec/*`、`mcp/builtin/media/*`），不引入 Node、LibreOffice、Pandoc 等外部运行时；新增 Rust 依赖需 MIT/Apache 兼容且体积可控。

## 一、结论先行：docx 为什么「没有格式」

1. **工具根本没下发**。`fs_export_docx` 在 [mcp.rs](file:///d:/MyProject/myAgent/src-tauri/src/commands/mcp.rs#L424-L430) 属于「低频按需」写入工具，只有当前会话历史里调用过才会注入。新会话里模型手里没有这个工具，只能说「无法导出」或改用 Markdown。→ **P0 一行修复**。
2. **排版内核存在，但学术细节不足**。[docgen](file:///d:/MyProject/myAgent/src-tauri/src/fs/docgen) 已实现封面、目录域、三线表、页眉页码、Heading 大纲级别；缺口集中在：中文字体与字号规范、标题自动编号、图表题注编号与正文交叉引用、参考文献悬挂缩进、脚注、分节页码、公式。

### P1 · docx 学术排版（M）

3. **标题自动编号**：`一、` / `1.1` / `1.1.1`，仅在用户未手写编号时生成；标题文字写入 Word 样式，保证导航窗格可用。
4. **题注与交叉引用**：Markdown 里表格上一行「表 1 参数对比」、图片下一行「图 1 系统架构」识别为 Caption 段落；`[@fig1]` / `[@tab1]` 在渲染阶段替换为「图 1」「表 1」并按出现顺序重编号。
5. **参考文献**：`## 参考文献` 下的行用 `Numbering` 生成 `[1]` 编号 + 悬挂缩进，支持 GB/T 7714 常见的「作者. 题名[文献类型]. 出版地: 出版者, 年.」格式提示。
6. **分节页码**：[writer/document.rs](file:///d:/MyProject/myAgent/src-tauri/src/fs/docgen/writer/document.rs) 用 `Section` 拆「封面 / 目录 / 正文」三节：封面无页码、目录罗马数字、正文阿拉伯从 1；页眉保留文档标题。
7. **脚注**：Markdown `[^1]` + 文末 `[^1]: 内容` → `add_footnote_reference`。
8. **公式（降级方案）**：`$$...$$` 先渲染为居中斜体文本 + 右侧编号 `(1)`；OMML 留作后续评估（需 fork 库），不阻塞本期。

验收样例：一份含封面、摘要、关键词、三级标题、两张图两张表、脚注、10 条参考文献的论文，Word 打开后：导航窗格层级正确、题注连续、目录可 F9 更新、页码分节正确。

### P2 · pptx 结构与版式（M）

在 [slides.rs](file:///d:/MyProject/myAgent/src-tauri/src/mcp/builtin/media/slides.rs) 与 [tool_spec/media.rs](file:///d:/MyProject/myAgent/src-tauri/src/mcp/tool_spec/media.rs) 上扩展，不换库：

5. **页脚页码**：统一文本框「文档标题 · 第 N 页」，封面与节页不显示。
6. **字号层级**：标题 30pt、一级要点 17pt、二级 15pt；每页超过 6 条自动降级为两级或拆页。

### 8.2 文档模板体系

#### 8.2.1 设计原则：模板表驱动，不再扩枚举

现在 `Profile` 是 4 值枚举 + `match` 出两套样式；再往里加公文、通知、纪要会变成「枚举 × match」爆炸。改为：

```
fs/docgen/templates/
├── mod.rs        Template 结构 + 注册表 + detect() + style_of()
├── official.rs   公文（GB/T 9704—2012）
├── academic.rs   论文 / 学位论文
├── lab.rs        实验报告
├── practice.rs   实践 / 调研报告
├── business.rs   工作总结 / 通知 / 会议纪要 / 方案
└── numbering.rs  三套编号方案 + 手写编号检测
```

`Template` 字段（全部是纯数据）：

```rust
pub struct Template {
    pub id: &'static str,          // "paper" | "official_notice" ...
    pub name: &'static str,        // 中文名，用于工具回执
    pub profile: Profile,          // 语义分类：Academic / Official / Business（新增）
    pub toc: bool,
    pub three_line: bool,
    pub numbering: Numbering,      // CnAcademic / CnOfficial / Simple
    pub skeleton: &'static [&'static str], // 缺失章节时的建议标题
    pub hints: &'static str,       // 仅随工具描述或回执返回，不进系统提示词
}
```

- `Profile` 收敛为**语义分类**：`Academic`（论文/实验/实践）、`Official`（公文）、`Business`（总结/通知/纪要/方案）、`General`；保留旧值 `parse` 别名映射，避免破坏现有调用与测试。
- `templates::style_of(id)` 在 `DocStyle::for_profile` 结果上做**字段级覆盖**（字体/字号/行距/边距），不复制结构体。

| `official` | 正文三号仿宋_GB2312、标题二号方正小标宋 | 固定 29pt（每页 22 行） | 上 37 / 下 35 / 左 28 / 右 26mm | 一、/（一）/1. | 标题、主送机关、正文、附件说明、发文机关署名、成文日期、抄送、印发 |
| `lab` | 宋体小四、黑体标题 | 1.5 倍 | 同论文 | 一、/1. | 实验目的、环境与工具、原理、步骤、数据记录、结果分析、结论、思考题 |
| `practice` | 宋体小四 | 1.5 倍 | 同论文 | 一、/1.1 | 背景、方法与对象、过程、发现、问题、建议、附录 |
| `summary` | 微软雅黑 11pt（或宋体小四） | 1.15 倍 | 上下 2.54 / 左右 3.17cm | 一、/（一） | 概述、完成情况、亮点与数据、问题、下一步计划 |
| `notice` | 仿宋三号 | 固定 29pt | 公文边距 | 一、/（一） | 标题、主送机关、事由、要求、落款、日期 |
| `minutes` | 宋体小四 | 1.5 倍 | 常规 | 一、 | 时间地点主持、出席人员、议题、讨论要点、决议、分工与时限 |

公文细节（`official.rs`）：标题居中二号小标宋；正文首行缩进 2 字符；成文日期右空四字；附件说明另起段；`发文字号` 形如「××〔2026〕1 号」由正文首行识别，不做自动编造。

#### 8.2.3 自动识别（替代当前 9 个关键词）

`templates::detect(title, body)` 打分：标题命中权重 3、正文前 400 字命中 1；特征加权（`〔20xx〕` +3 → official；`摘要/关键词/参考文献` +2 → paper；`实验目的/实验步骤` +2 → lab；`调研/实习` +2 → practice；`会议纪要/出席` +2 → minutes；`通知/特此通知` +2 → notice；`本周/本月/季度/完成情况` +1 → summary）。最高分胜出，同分按「公文 > 论文 > 实验 > 实践 > 总结 > 通用」。识别结果写进工具回执（「已按『公文』模板排版」），便于用户纠偏。

#### 8.2.4 编号与题注

- `numbering.rs` 提供 `CnAcademic`（1 / 1.1 / 1.1.1）、`CnOfficial`（一、/（一）/1.）、`Simple`（一、/1.）。
- 手写编号检测：标题以 `一、`、`（一）`、`1.`、`1.1` 开头则不自动加编号，避免「一、一、」。
- 题注沿用现有 `TableText/Caption` 样式，按模板决定题注位置（论文表上、公文表上、通用表上）。
- 每条规则都用「输入 Markdown → 断言 document.xml 前缀」的单测覆盖，不依赖人工看文件。

#### 8.2.5 工具与提示词

- `fs_export_docx` 新增 `template` 参数（枚举 8 值），`profile` 保留并映射；未传 `template` 时走 `detect`。
- 写作规范**不进系统提示词**（1400 字符上限）：模板 id 与「何时用哪种」压缩成一句进工具描述；`skeleton/hints` 由工具在「正文缺章」时以回执形式返回，按需消费。

#### 8.3.3 接入策略（保守、可预期）

`slides_export` 新增 `template` 参数：

1. **补骨架，不覆盖**：用户已给出的页一律保留；模板只补齐缺失 role（按页序插入），骨架页标题用 `title_hint`，bullets 只写「待补充：…」占位，并在回执列出缺数据页。
2. **主题回退**：未显式传 `theme` 时用模板主题（`defense/group-meeting` → `academic`；`work-summary/progress` → `corporate`；`data-analysis` → `modern`）。
3. **缺数据告警不阻断**：`need_data` 页没有 chart/table/KPI 时，回执附「建议补充数据」清单，仍正常出包。
4. **无模板时行为不变**：完全未传 `template` 时走现有逻辑，保证既有调用与测试零回归。

`academic` 主题新增到 [slides_render.rs](file:///d:/MyProject/myAgent/src-tauri/src/mcp/builtin/media/slides_render.rs) 的 `theme_of`：深灰标题、细分割线、无大面积色块、页脚灰字。
