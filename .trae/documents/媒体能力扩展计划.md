# 媒体与检索能力扩展计划（含本轮追加项）

## Context

本轮要解决两类问题：

1. **交互缺陷**：输入区「添加附件」的来源菜单（本地上传 / 从附件中心导入）向上展开时被页面顶部的任务条遮住；附件中心导入选择器只有单列列表，预览信息不完整、宽度固定。
2. **能力缺口**：对话内无法生成图片、无法产出 PPT、无法识别图片文字；全局搜索实际只过滤会话标题，`search_all` 已具备的多源检索没有被搜索面板使用。

约束：沿用现有 provider / 工具 / 产物 / FTS 架构；新增逻辑一律拆文件，单文件不超过既有行数守卫（Rust 700 行、CSS 与 TS 按 `src/lib/fileSize.test.ts`）。

---

## 优先级与实施顺序

| 顺序 | 事项 | 优先级 | 难度 | 依赖 |
|---|---|---|---|---|
| 1 | 附件来源菜单遮挡修复 | P0 | XS | 无 |
| 2 | 附件中心导入预览与宽度 | P0 | S | 1 的浮层定位 hook |
| 3 | 全局搜索多源化 | P1 | M | 无 |
| 4 | 图片生成 `image_generate` | P1 | M | 无 |
| 5 | PPT 生成 `slides_export` | P2 | M | 4 的产物链路 |
| 6 | 图片 OCR `ocr_extract` | P3 | L | 模型打包与 MNN 验证 |

理由：前两项是现有操作路径上的阻断性缺陷，改动小、收益直接；搜索多源可复用已存在但闲置的 `search_all` 与 `GlobalSearch` 逻辑；媒体三项需要新增依赖，放在交互与检索稳定之后。

## 一、附件来源菜单被任务条遮挡（P0）

**现状**：`src/components/composer/ToolBar.tsx` 的 `srcMenu` 直接渲染在 `.attach-src-wrap` 内，`.pin-menu` 以绝对定位向上展开；页面顶部的任务条层级更高时，菜单顶部被压住。同文件的「思考强度」菜单已经解决过同类问题：`createPortal` + 实测锚点矩形，算出 `bottom / left / maxHeight`。

**方案**

- 新建 `src/components/composer/usePinMenu.ts`：入参 `anchorRef` 与 `open`，返回 `{ pos, sync }`；逻辑照搬 `syncThinkPos`（[ToolBar.tsx](file:///d:/MyProject/myAgent/src/components/composer/ToolBar.tsx#L86-L103)），额外加 `top` 可用空间判断：锚点上方高度 < 菜单最小高度时改为向下展开，否则向上；`resize` 与窗口全屏变化时重算。
- 附件菜单改用 `createPortal` 渲染到 `document.body`，套用同一 `fixed` 定位与 `--z-menu` 层级；「思考强度」改为调用该 hook，删除重复的定位代码。
- `.pin-backdrop` 一起 portal，避免遮罩被输入区容器限制。
- 菜单最小宽度 200px，`maxHeight` 用可视空间与 `240px` 取小值，内部滚动。

**测试**：把定位计算抽成纯函数 `computeMenuPos(anchorRect, viewport, menu)`，在 `usePinMenu` 同目录加单测，覆盖上方空间不足时向下翻转、左右钳制、窄窗。

**涉及文件**：`ToolBar.tsx`、新增 `usePinMenu.ts`、`src/styles/chat/composer.css`（`.attach-src-menu` 定位改为 fixed）。

## 二、附件中心导入选择器：预览信息与自适应宽度（P0）

**现状**：`AttachmentCenterPicker.tsx` 已有文件名、来源会话、摘要三行信息，但摘要只在行内单行展示，宽度固定 720px，没有独立预览区域；`AttachmentEntry.meta.summary` 与 `source session_title` 已由 `list_all_attachments` 返回，无需改后端。

**方案**

- 布局改为两栏：左侧列表 `flex:1`，右侧预览栏 `300px`（`--ui-scale` 缩放）；容器宽度 `min(calc(960px * var(--ui-scale)), 94vw)`，内容宽度不足 720px 时隐藏预览栏、回到行内摘要（纯 CSS 媒体查询，不写 JS 分支）。
- 预览内容：文件名、来源会话（可点击跳到来源会话）、类型 · 大小 · 驻留块数、解析摘要（`summary`，缺省显示 `extract_note` 或「未解析」）、入库时间。
- 交互：行点击仍只负责勾选；鼠标悬停 / 键盘聚焦时更新预览，默认展示第一条；勾选后预览保留最后一个操作项，避免列表跳动。
- 把预览栏拆成 `AttachmentPreviewPane.tsx`，与选择器同目录，选择器只保留列表与导入逻辑。

**测试**：Vitest 覆盖「悬停切换预览」「未解析条目展示原因」「窄容器隐藏预览栏的类名切换」。

**涉及文件**：`AttachmentCenterPicker.tsx`、新增 `AttachmentPreviewPane.tsx`、`src/styles/tools/attachment.css`。

## 三、全局搜索多源化（P1）

**现状**

- 入口在 `Titlebar` / `Sidebar`，`ui.searchPaletteOpen` 控制；`Sidebar.tsx` 内的 `SearchPalette` 只对本地 `sessions` 做标题过滤，没有调用后端。
- `commands/search.rs::search_all` 已覆盖会话标题、消息全文（`messages_fts` + trigram）、`memory.md`、知识库 `notes_fts`，返回 `sessions / messages / memory / notes`。
- `src/components/GlobalSearch.tsx` 实现了多分组展示与跳转，但已没有调用方（死代码）。
- 附件没有独立表：元数据在 `messages.attachments` JSON（含 `summary`、`extracted_text`），正文块在 `doc_chunks`（`doc_name / kind / content / session_id`）。

**方案（后端）**

- `SearchResults` 增加 `attachments: Vec<AttachmentHit>`；新结构放 `search.rs`：
  `AttachmentHit { path, name, kind, session_id, session_title, message_id, branch_id, snippet }`。
- 新增 `fn search_attachments(conn, q) -> Vec<AttachmentHit>`：扫描 `messages.attachments LIKE '%q%'`，反序列化后匹配 `name` / `summary` / `extracted_text`，生成命中前后 40 字片段；按 `path` 去重；`LIMIT 10`；转义与现有 `like` 一致。仅扫带附件的消息（`attachments <> '[]'`），量级可控。
- 若后续需要检索解析全文，再扩展 `doc_chunks` 的 `LIKE` 或独立 FTS；本轮只做「摘要与文件名」，不改 schema、不升 `SCHEMA_VERSION`。
- `search.rs` 已 256 行，附件逻辑放新文件 `src-tauri/src/commands/search_attachments.rs`，`search.rs` 只调用并组装结果。

**方案（前端）**

- 从死代码 `GlobalSearch.tsx` 中抽两个文件：`src/components/search/useSearchAll.ts`（250ms 去抖、空词短路、错误态）与 `SearchResultList.tsx`（分组渲染 + 跳转），删除 `GlobalSearch.tsx`。
- `Sidebar.tsx` 的 `SearchPalette` 改为：输入后走 `useSearchAll`，分组展示会话 / 消息 / 记忆 / 笔记 / 附件；无结果时提示；方向键上下移动、Enter 打开；跳转逻辑沿用原 `GlobalSearch`（消息带 `?msg=`，笔记跳 `/notes`，附件定位到来源消息）。
- 面板宽度提升到 `min(calc(680px * var(--ui-scale)), 92vw)`，分组标题带数量；附件项右侧显示类型徽标。

**测试**

- Rust：`search_attachments_on` 使用内存库，覆盖中文摘要、文件名命中、去重、上限、`%` 转义。
- Vitest：`useSearchAll` 去抖与空态；`SearchResultList` 分组顺序与跳转参数。

## 四、图片生成 `image_generate`（P1）

**参数**：`prompt`（必填，≤4000）、`size`（`auto` / `1024x1024` / `1536x1024` / `1024x1536` / `1792x1024` / `1024x1792`，默认 `auto`）、`model`（可选覆盖）、`path`（可选，工作区内）。

**接入**

- 规格：新建 `src-tauri/src/mcp/tool_spec/media.rs`，在 `write_tool_defs()` 末尾拼接；`ALL_BUILTIN_TOOL_NAMES` 与 dispatcher 白名单测试自动覆盖。
- 执行：新建 `src-tauri/src/mcp/builtin/media/image.rs`，在 `builtin/mod.rs` 增加 `media::handles` 分支；空参立即报错，不联网。
- 下发：`commands/mcp.rs` 的 `always` 数组加入 `image_generate`（低频写历史激活对新工具无效）；`presets/builtin.rs` 的 `standard.include` 增加该工具，`economy` 不加。
- 审批：沿用写工具 Medium 风险，工作区档下逐次确认。

**配置与请求**

- `AppSettings` 新增 `image_provider_id` / `image_model`（照 `summarize_provider_id` 先例）；设置页新建 `src/pages/settings/MediaView.tsx`，在 `constants.ts` 的「能力」组加入 `media` 导航项。
- 密钥复用 `keys::resolve_spec` 与现有 keystore 槽位；独立 `reqwest::Client`（连接 15s、总 120s）；`gpt-image-*` 不传 `response_format`，其余传 `b64_json`；`b64_json` 优先，`url` 兜底（仅 https、≤20MB）；4xx 不重试，网络错误 / 5xx 重试一次。
- 落盘 `<workspace>/outputs/images/<时间戳>-<slug>.<png|jpg>`，按魔数定扩展；调用 `crate::deliverables::present` 登记 `kind:"image"`。
- 返回：`已生成图片：<相对路径>（WxH，已登记产物）`；失败：`图片生成失败：<原因>。可在设置 → 能力 → 媒体中检查服务商与模型。`

**前端**：`OutputCards.tsx` 的 `ImageCard` 已支持按需读取与放大，仅补「另存为」。

## 五、PPT 生成 `slides_export`（P2）

**参数**：`path`（可选，默认 `outputs/slides/<title>.pptx`）、`title`（≤120）、`theme`（`minimal`）、`slides`（1..30；每页 `title`≤80、`bullets`≤8 条每条≤200、`notes?`、`image?`）。

**实现**

- `Cargo.toml` 增加 `ppt-rs = "0.2"`（Apache-2.0，纯 Rust，支持创建、读取、校验、图片）。
- 新文件 `src-tauri/src/mcp/builtin/media/slides.rs`：16:9，简约主题（微软雅黑、要点 + 页码）；`image` 经 `fs::paths::resolve` 校验后嵌入；写前走 `backup::snapshot`。
- 成功后 `present(..., kind:"slides")`；失败回退同目录 `<stem>.outline.md` 并登记文本产物，返回 `ok=false` 与回退说明。
- 规格放 `tool_spec/media.rs`；`always` 数组加入；`standard.include` 增加。

**前端**：`.pptx` 复用现有文件卡（打开 / 定位 / 复制路径），不新增预览器。

## 六、图片 OCR `ocr_extract`（P3）

**参数**：`path`（必填，工作区路径或附件路径）、`lang`（`chs` / `eng` / `chs_eng`，默认 `chs_eng`）、`max_lines`（1..1000，默认 400）。

**归属**：只读工具（读图返回文本），加入 `readonly` 规格，随只读工具全量下发，不触发审批。

**依赖与模型**

- `ocr-rs = "2"`（Apache-2.0，PaddleOCR + MNN）；关闭 GPU，仅 CPU（feature 名以 `cargo add` 后元数据为准）。
- 模型放 `src-tauri/resources/ocr-models/`（PP-OCRv6 small 的 det / rec `.mnn` + `ppocr_keys_v6_small.txt`），`tauri.conf.json` 的 `bundle.resources` 声明；dev 回退 `CARGO_MANIFEST_DIR/resources/ocr-models`，允许 `<data_dir>/ocr-models` 覆盖；`resource_dir` 在 `lib.rs` setup 写入 `paths` 的 OnceLock。

**执行**

- `OnceLock<Result<OcrEngine, String>>` 懒加载 + `spawn_blocking` + 静态 `Semaphore(1)`；仅 png/jpg；长边 >2000px 降采样；缺模型立即返回路径与安装指引，不自动下载。
- 输出：首行行数与平均置信度，之后 `文本<TAB>置信度`；超 12000 字符截断；空结果给出调整建议。

## 九、风险

- `ocr-rs` 的 feature 名与 MNN 预编译需首日验证；失败则暂用 Windows 内置 OCR 过渡（需确认）。
- 模型与 MNN 使安装包增加约 20–40 MB，首次 OCR 初始化 1–3 秒。
- 国内图像端点的尺寸与返回结构差异，按「b64 → url → 明确报错」处理，不静默重试。
- 附件 JSON 扫描在超大历史库上有开销，已限制 `LIMIT 10` 且只扫带附件的消息；必要时再迁移到 FTS。
- 新增两个常驻写工具会抬高每轮 token，完成后用 `session_events.breakdown` 核对增量。
